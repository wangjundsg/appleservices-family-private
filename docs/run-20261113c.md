## 五、根因：`captchaLocator` 与 `/captcha` 的竞态（2/3 尝试死在这里）

### 5.1 触发链

1. `fillForm(fr)` 填完 9 个字段（`create-account.cjs:795-808`）；
2. 紧接着 `captchaLocator(fr, …)`（`:829`）→ `observeCaptchaImages` + `lib.pickCaptchaImage`；
3. 此刻 `<img>` 已在 DOM，但 `/captcha` 的 201 还没回来 → `naturalWidth=0`；
4. `pickCaptchaImage` 判不可用 → `captcha-unavailable` → `throw`，**整轮直接失败**（不是重试一轮）。

三次的时序差异（同一天、同一台机器、同一套脚本）：

| 尝试 | `at=form` → 放弃取图 | 放弃 → `/captcha` 201 | 结果 |
| --- | --- | --- | --- |
| UK | 291ms | +202ms | 失败 |
| FR | 338ms | +1012ms | 失败 |
| NL | —（图已加载，`natural=[160,70]`） | — | 通过取图，死在号码 |

### 5.2 为什么算「工具侧」而不是「出口被挡」

- 同一出口、同一分钟前后的浏览器探针 `ok=true`，真图 160×70、`near=1`；
- 失败的运行里 `/captcha` 返回 **201**（不是 403/503），只是比取图晚到；
- 两次失败都发生在**表单第 1 轮、300ms 级窗口**，第 2 轮起从未有机会发生（第一轮就 throw）。

### 5.3 建议（本轮只记录，不改代码）

1. `captchaLocator` 前置一个「等图」轮询：`waitForFunction(img => img.complete && img.naturalWidth > 0, timeout 8~10s)`，
   超时再判「不可用」；把竞态窗口从 300ms 缩短到「图真的没来」。
2. `captcha-unavailable` 在 `submitAttempted=false` 时**不应该终止整轮**：表单还没提交，什么都不可能被烧，
   重试一轮（或等 1~2s 重取）即可，代价为零。
3. `--captcha-wait <ms>` 之类的显式等待参数，供慢出口（本轮的住宅代理首次握手 33~45s）使用。
4. 顺带：`--phonecc` 参数（见 2.3）——现在主链写死 `US`，非 US 号码根本没法用。

## 六、其它发现

### 6.1 NL 号池（hero `wx` / country=48）只有 M2M 段

两次抽号都是 `+31 097x`（nsn 11 位）。这类号结构上不可能是移动号，苹果表单层直接 `Enter a valid phone number.`。
**结论：NL 这一档在当前池下不可用**，第三次尝试换 FR 是对的（FR 号 `type=mobile`、nsn 9 位）。

### 6.2 `--auto-refund` 撞最短持有期，三次都没自动退成功

三次 `final` 前都跑了 auto-refund，三次都是：

```json
{"title":"EARLY_CANCEL_DENIED","details":"Activation cannot be cancelled at this time. Minimum activation period must pass.",
 "info":{"minActivationTime":120}}
```

即 `minActivationTime=120s` 之前 hero 拒绝任何取消。四次退款全部靠**人工在冷却后补 `setStatus=8`** 才拿到 `ACCESS_CANCEL`。
建议：`--auto-refund` 改成「失败后等到 120s 再退」或「失败时只记录待退清单」，否则每次都留下一个挂着钱未退的号。

### 6.3 `proxyselect` 需要 `-url`/`PROXY_TEMPLATE`

任务书给的是 `proxyselect -dir … -provider dataimpulse -country US -ports … -state …`，直接跑会：

```
proxyselect: error=usage detail="provider dataimpulse needs a template: pass -url or set PROXY_TEMPLATE"
```

必须补 `$env:PROXY_TEMPLATE='http://<user>:<pass>@gw.dataimpulse.com:<port>'`（模板里端口会被 `-ports` 覆盖）。
另：不带 `-preflight-url` 时输出 `status=0 ip= recorded=false`，只落 lease 不验证出口——出口可用性靠 `preflight-browser.cjs` 判，符合第二轮 §4.2 的结论。

### 6.4 出口健康度

| 端口 | 浏览器探针 | 说明 |
| --- | --- | --- |
| 10021 | ok 44.7s | 出口可用，但同一出口的建号死在取图竞态 |
| 10031 | **`no-widget-frame` 44.5s** | frame=false，widget 帧没出来（第二轮见过同样形态）→ 释放换口 |
| 10032 | ok 33.6s | 建号取图正常（`natural=[160,70]`、6 轮哈希均不同） |

即：**探针通过 ≠ 建号能过**（10021/10041 都是探针 ok、建号第一轮就挂）。探针只能筛「frame 都不出」的死口。

## 八、结论与下一步

**结论：3 次尝试 3 次失败，0 账号，全链仍未跑通到「建号成功」，手机步本轮一次都没到达。**

按优先级：

1. **先修取图竞态**（§5.3 第 1、2 条）——这是当前最大阻塞：3 次尝试里 2 次在 300ms 窗口内报废，
   再多的身份也只会重复这个失败。修法很轻：等图 8~10s + 未提交时允许重取。
2. **补 `--phonecc`**（§2.3）——否则 UK/NL/FR 号码根本进不了流程。
3. **NL 档先停**（§6.1）：该池只有 M2M 号，除非换供应商/换号段，否则每次都是 `Enter a valid phone number.`。
4. **号码筛选前置**：买号后用 libphonenumber 断言 `type=mobile` 且 nsn 长度合规（本轮 NL 两次都是靠这个判出死号的），
   别等表单红字才发现。
5. 修好 1+2 之后重跑一次 UK 或 FR（**全新四件套**），才可能真正看到手机步的 `Security Code Error` 与那四点观察。
