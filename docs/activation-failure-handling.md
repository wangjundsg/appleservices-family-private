# 激活初始化失败的定位与恢复

本次修复处理本机激活链路，不改变 Apple 注册判定。注册的 `-34607001` 与激活初始化的 TLS 握手失败不能归为同一个错误。

## 已确认的问题

- 调用问题：用面板脱敏的 `account` 字段匹配完整邮箱，会误判添加失败。`POST /api/accounts/add` 现在返回 `account_id`；即使后续初始化失败，只要账号目录已保存，也返回该 ID。重复添加同一邮箱返回原 ID，不重新分配设备身份。调用方应按 ID 查询或继续连接。
- 网络与配置问题：一次 ADI 初始化在账号认证前发生 `unexpected EOF during handshake`。相同设备资料通过已经验证支持 HTTP CONNECT 的同一代理端点完成了初始化。SOCKS URL 直接作为该原生模块的 HTTPS 代理未获验证；不能推断任意 SOCKS 端点都支持 HTTP，更不能自动改写协议或换出口。
- 代码问题：原生错误被统一丢弃，且退出与最后一条 RPC 回复同时到达时可能丢失回复。现在保留白名单错误类别，并先消费已收到的最终回复。原始响应、代理凭据和账号元数据仍不输出。
- 推送初始化此前吞掉了工具已经给出的失败阶段。现在区分本机初始化、读取身份、连接 APS、保存证书，并明确告知账号目录已保留、尚未启动登录。首次历史 APS 失败没有留存具体阶段，不能追认它也是 TLS 问题。

## ADI 专用代理

启动面板或 worker 的进程可设置 `APPLESERVICES_NATIVE_HTTP_PROXY`，值为完整的 HTTP/HTTPS 代理 URL，必须带有效端口，用户名中的模板必须预先解析。凭据从本机私有配置注入进程环境，不放命令行、仓库、日志或 API 回执。

这个设置仅映射到 ADI Python 子进程的大小写 `HTTP_PROXY` / `HTTPS_PROXY`，覆盖该子进程继承的代理和 `NO_PROXY`，不更改 Go 登录、APS、NAC 的路由。未设置时保留既有环境行为。不会自动读取注册供应商代理、换出口或回退直连。

无效配置在停止现有 worker、启动推送初始化和账号登录之前拒绝。客户端直接启动时也会在创建 helper 前拒绝。配置正确不代表代理一定可达；TLS、连接、超时仍需按实际阶段处理，不自动重放账号登录、验证码或未知结果的写请求。

## 调用与验收顺序

1. 先按 `account_id` 查看现有状态。已激活且在线时不再次添加或带密码启动；已有 worker 的带密码 `start` 是显式重新登录操作。
2. 添加回执含 `account_id`、`ok=false` 时保留该账号。界面会选中它并退出添加窗口；修复本机依赖或网络后连接同一账号，不重新建目录。
3. `ok=true` 的启动回执只代表后台开始连接。继续观察 `awaiting_sms`、在线状态和激活状态，不能据此宣称激活成功。
4. 激活成功仍要求同账号的 GSA、条款（若要求）、NAC、delegate 状态与 MME token、实际 quota 读取全部成立。初始化失败不能触发重新购买邮箱/号码或重新注册。

## 回归验证

`go test ./nativeadi ./internal/dashboard ./internal/control ./cmd/trusted-device` 覆盖代理隔离、退出竞态、错误脱敏、部分添加失败后的稳定 ID 和既有激活逻辑。

`python -m unittest discover -s nativeadi -p test_bridge_errors.py` 验证原生二进制错误分类不泄露元数据；面板脚本另做 Node 语法和交互回归。

构建新版本后必须核对实际面板进程和其 `-worker` 路径；源码或磁盘默认二进制更新，不等于运行中的旧进程已经更新。保留已成功的会话，不为部署验证重复发短信。
