## 4 结论

1. **指纹本身没问题**：两组三要素（请求 OS / 服务端配置 OS / 页内实测 platform+UA）全绿，locale、tz、出口国家也全绿。OS 变量是被干净地下发的。
2. **两组都撞同一堵墙**：`Your account cannot be created at this time`。差别在于走到哪一步：
   - M 死在表单（4 次挑战，前 3 次是本轮取码通道读错，第 4 次提交时苹果直接硬拒）；
   - W 表单与邮箱验证都过了，短信码也收到了，硬拒出现在手机步骤。
3. **哪个 OS 更适合**：按本轮证据 **Windows**——表单被接受、邮箱验证通过、短信码到达；macOS 一次都没让苹果接受提交。但 M 的硬拒被"3 次验证码读错"污染过（提交次数 4 vs 1），不是纯净的 OS 判决，要下结论应让 M 用同样的一次过通道再跑 1 个号。
4. **共同嫌疑（与 OS 无关）**：表单国家锁死 `United States` 而号码是 +44 GB；hero 共享号池的号码大概率被反复用过。这两条比 OS 更能解释同一句硬拒，建议下一轮把表单国家与号码国别对齐（GB 号 + GB 国家）。
