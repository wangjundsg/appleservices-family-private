# 本机 Chrome 路径与验收边界

面板“新建 Apple ID”可选择本机 Chrome 或 Forge 指纹浏览器。选择在当前浏览器记忆，任务将 `browser_mode` 固定到私有清单；旧任务缺省仍为 Forge。两种方式共用现有 `pipeline.py → create-account.cjs → dashboard_handoff`，没有新增注册或激活 HTTP 接口。

本机 Chrome 直接启动本机安装的 Chrome，不调用 Forge，也不要求 Forge 凭据。使用浏览器原生环境，不加载创建器旧的指纹覆盖。新任务默认使用本机 OCR；失败换图、远程兜底和自动重试见下文。旧的显式人工配置仍可读取答案文件。自动邮箱读取、同会话资源更换与新码交接共用既有创建和面板交接流程。

本机网络可选择直连，或注册资源中的 `localBrowserProxy`。代理必须为带显式端口、无凭据的本机 HTTP、HTTPS 或 SOCKS5 地址；不自动寻找端口或切换出口。选定代理复制进该任务，修改资源设置不迁移旧任务。Forge 继续使用自己的代理与预检。

原激活启动器未加载注册配置和供应商环境，运行面板因此显示注册资源缺失。`tools/start-activation-dashboard.ps1` 增加可选 `-RegisterConfig`，复用 `provider-environment.ps1` 加载已有凭据；`-AllowPurchase` 必须同时指定注册配置。默认仍不购号、不恢复后台任务。私有配置和凭据不提交。

葡萄牙 Hero 的既有真实回执显示一小时有效期，旧代码只接受最多半小时。本轮先用脱敏回执复现错误，再将葡萄牙普通订单的有效期上限修为一小时；仍核验实际起止时间、金额、币种和后续接码能力，不延长供应商给定租期。

## 单号实网发现与修复

新版面板已部署，三个既有 worker 的 PID、启动时间和映像路径未变。使用原 API 购买一个 Gmail 订单（700 VND），经现有面板绑定后启动本机 Chrome、葡萄牙、仅建号和激活的任务。原购号器取得一个葡萄牙号码（0.065 USD）。

首次执行在打开浏览器前返回 `usage / invalid activation expiry`，未向 Apple 提交注册。原因是共享 JS 生命周期仍只接受未来 30 分钟以内的到期时间。新增失败测试后，将上限与既有支持的一小时、一天租期对齐，仍使用订单实际到期时间。

另外，本地参数错误被旧编排误记为创建拒绝，并进入换号分支。现在退出码 2 单独记为 `registration_input_invalid`，保留号码，不结算或自动换号；只在已确认没有提交的情况下允许原任务恢复。换号分支同时保留供应商和租期策略，防止回退到默认供应商。

已核实原订单仍为 `PURCHASED / STATUS_WAIT_CODE`，只有一次号码购买。旧分支丢失的任务短信字段从同任务冻结清单、原创建输入和已购买回执恢复，原证据备份到私有目录。随后使用既有 `pipeline.py resume` 继续同一任务，无新购号、无更换邮箱、无直接调用 Apple 创建接口。实际浏览器已进入 `form_running`；完整实网结果待后续记录。

## 本机模式后续优化目标与重启排查记录

用户要求先中文、后英文，统一验证码等待时间，完善本机 OCR 和全部交互节奏。后来明确修正 OCR 顺序：本机识别不出先换图，连续最多三次，然后使用 Forge 原有的 YesCaptcha 识别兜底；远程失败在同一窗口重走识别流程，不等待人工、不重开注册。

意外重启并非用户重新发起任务。已定位的因果链是：人工校验在页面完成，但脚本只轮询答案文件；等待超时退出码 1 被外层归入 `registration_rejected`；`create_with_replacement` 自动换号并再次打开创建器。现在本机模式创建器退出不再触发这个重开分支。只有在浏览器启动前确认号码不能后续接码的供给检查仍允许原有有界资源更换。人工直接推进页面时，会核对验证标题、验证码输入框和创建表单是否消失，然后接续当前页面；OCR 子进程改为异步，避免识别期间阻塞浏览器事件。停止后的任务也不再以瞬时 `form_running` 掩盖终止原因。

### 当前本机策略

| 环节 | 行为与边界 |
| --- | --- |
| 邮箱验证码 | 等待 180 秒，页面重发一次，再等 180 秒；无结果时先确认可退回完整创建表单，再通过现有 OTPGmail 订单 API 获取一个替换邮箱。 |
| 邮箱更换 | 每任务最多一次，沿用原仓库，每次上限 700 VND，要求原购资源开关授权。写入购买意图、使用幂等键、保留订单、预留新邮箱，再更新任务身份与取码文件，最后通知浏览器。SMS 账本仍绑定原始归属，激活交接读取新邮箱。其他邮箱来源不擅自购买替换。 |
| 手机验证码 | 等待 180 秒，页面重发一次，再等 180 秒；无结果进入原同会话换号流程，沿用冻结供应商、国家和费用限制。每个号码只重发一次，每任务只做一次同会话换号。 |
| 本机 OCR | 默认 ddddocr beta 与普通模型一致性策略：保留大小写，只接受 4–6 个 ASCII 字母数字，两个结果一致且各自模型置信度不低于 0.85；损坏或空白图片拒绝识别。置信度不是实测正确率。 |
| 换图与兜底 | 本机读不出，最多连续换图三次；每次清旧答案、完成失焦校验、点击页面自身换图按钮，确认图片变化后再识别。单次换图未变化计入三次上限，不重复本机识别旧图；之后调用 Forge 同一 `solver.py --provider yes --skip-local` 远程路径。远程仍失败，下一轮在当前窗口换图重试；最多四轮，受当前图形校验总时限（主表单 240 秒、后续步骤 180 秒）及号码租期共同约束。同一图片在当前创建器内只交远程一次，持续卡在旧图会明确停止，不无限付费、转人工等待或重新建号。 |
| 中文与英文 | 验证标题优先于页面引用的邮箱地址；继续、重发、换号、换图分别匹配，包含实际简体中文“使用其他电话号码”。支持可访问名称，跳过隐藏按钮，刷新控件不能被误当作提交。 |
| 操作节奏 | 下拉先用 Home / End 确定起点，再走较短键盘路径，跳过隐藏和禁用项，按键间隔 100 毫秒，确认后留 300 毫秒稳定时间；输入错误不再吞掉，旧值不重复追加，验证码清理并读回。点击结果不明确时，本机模式不会强制再点。 |

Forge 的等待策略、创建方式和指纹配置保持原有配置；上表新时限与 OCR 流程只在本机任务启用。新邮箱与号码供应商的真实可用性、Apple 当前页面可回退情况和最终激活成功仍需下一次实网验收，不以替身测试代替成功回执。

### 轻量开源 OCR 比较

查阅 [ddddocr 官方项目](https://github.com/sml2h3/ddddocr) 和 [PaddleOCR 官方文字识别模块](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/text_recognition.en.md)。本机现有 ddddocr 1.6.1；隔离环境另安装 PaddleOCR 3.7.0 / PaddlePaddle 3.3.1，下载 `en_PP-OCRv5_mobile_rec`，实测权重文件 7,772,315 字节。测试环境、模型权重、图片、标签均不提交。

使用公开字体生成 8 张简单字样和 32 张加入逐字旋转、曲线与噪点的合成图，均有事先生成的正确标签。以下为整串大小写完全一致的数量；不是 Apple 验证码准确率，也不能外推到真实图像。

| 方法 | 简单图：正确 / 接受 / 总数 | 干扰图：正确 / 接受 / 总数 | 干扰图整批耗时（含加载） |
| --- | --- | --- | --- |
| ddddocr beta | 5 / 8 / 8 | 13 / 32 / 32 | 1.34 秒 |
| ddddocr 双模型一致性 | 4 / 4 / 8 | 9 / 11 / 32 | 1.89 秒 |
| PP-OCRv5 英文 mobile | 7 / 8 / 8 | 10 / 18 / 32 | 7.55 秒 |

暂选 ddddocr 双模型一致性作为默认：在这组干扰图中误接受更少，较适合“读不可靠就换图，最后远程兜底”的策略。Paddle 的简单图结果更好，但干扰图没有证明更适合当前目标，不直接替换默认模型。`ocr.py --engine paddle` 与 `benchmark.py` 保留复测入口；后续应使用带可靠标签的真实样本评估，不能承诺少量训练样本就达到 90%。

### 国家选择失败排查（后续实网任务）

用户观察到国家列表反复滚动、无法选中，并报告姓名变化。原任务记录显示：姓名各写入一次，随后国家选择两次读回失败，抛出 `field_readback_failed / field_mismatch:country`，尚未提交创建表单。旧编排把该脚本退出错误地标为 `registration_rejected`；截图仍是创建表单，没有 Apple 拒绝创建的证据。不能仅凭当前日志断言姓名在页面上没有变化。

只读检查当前页面取得 245 项中文国家列表，没有隐藏项。用这份公开选项列表在本地有窗口 Chrome 复现：预期美国，旧选择方法首次落到墨西哥。原方法把 DOM 已提交的选中值当作弹出菜单的当前高亮起点，而高亮可以移动、DOM 值却要等 Enter 才提交，因此方向键计数会偏移。单独测试还发现隐藏项会被 Chrome 跳过，原 DOM 计数没有排除它们；这是额外漏洞，不是本次实网页面的隐藏项证据。

最小修复：每次先用 Home / End 建立确定起点，再按可选可见项计数；沿用键盘操作、逐键等待及选择后读回。实际中文列表连续两次选择均准确。补充有窗口长列表、高亮与 DOM 值分离、隐藏项的失败回归；原算法先复现失败，修复后通过。本机表单先稳定国家，再填写姓名；国家选择失败时不会开始写姓名。只有读回通过才记录 `field-verified`，选择动作本身改记 `selection-attempted`。

创建器向编排保留不含字段值的错误证据，本机字段不一致单独报告 `registration_field_mismatch`，不标成网站拒绝，不允许因此重开建号。排查阶段未重开或恢复原任务、未新增购买；已激活账号进程未触碰。真实任务的完整创建和激活仍未通过。

### 年份、号码误聚焦与第一次换图退出

后续任务已通过国家、生日和号码读回校验，停在首次本机 OCR 未接受后的换图等待：`frame.waitForFunction` 超过 10 秒，未进入第二次换图或远程兜底，旧分类仍把普通脚本异常归为注册拒绝。

焦点原因：共享字段助手用 Tab 触发失焦，会把焦点移动到 DOM 顺序的下一个控件；年份会访问尚未填写的邮箱，号码会访问说明按钮。现在本机字段助手对当前控件直接执行 blur，再由下一步明确定位目标；下拉、文字输入、邮箱/短信验证码和图形码均接入，Forge 保留原行为。本机生日先年、再月日，不提前访问邮箱。

换图原因在当前公开页面复现：对本来为空的图形码框执行 `fill("")` 使它聚焦；点击换图时，失焦校验重建按钮，导致没有换图请求。旧调用超时且请求数为 0；先完成失焦、再点击则请求数为 1 且图片变化。修复后同一个 helper 首次调用即发出 1 次请求并换图成功。没有填写真实身份、提交建号、购买资源或调用付费 OCR。

换图等待超时现在返回未变化结果，计入最多三次，不再直接抛出退出；图片没有变化时不重复本机 OCR，第三次后仍可交远程。同一图像的远程调用记录跨图形校验轮次保留，远程失败后继续有界换图，持续旧图不重复付费。明确的图形码终止证据报告 `registration_captcha_unresolved`，不再标为注册拒绝。

新增回归先复现失败，再验证修复：有窗口 Chrome 的年份/号码焦点、失焦时按钮重建、三次未变化后远程兜底、旧图远程去重，以及真实创建器的字段处理接线。Node 188 项、Python 编排 181 项全部通过。原实网任务未恢复或重开，面板和三个既有 worker 的 PID、启动时间未变；完整建号至激活仍待后续实网验收。

### 自动密码包含连续重复字符

后续截图显示密码规则错误“连续相同的字符太多”。仅检查私有文件的长度与最长连续重复数，确认请求、编排输入和创建器输入均为同一份 40 位密码，最长重复数为 3。两栏填写完成后的读回均为 40 位且与冻结密码相等，没有重复追加的记录；截图中的长度差不能当作填写完成后的不一致证据。未输出或提交密码内容。

根因是两个自动邮箱入口均用固定类别前缀加 18 字节随机数的十六进制编码生成密码，只核验字符类别，没有排除三连字符。[Apple 官方密码要求](https://support.apple.com/en-ca/guide/security/secbd5822138/web)明确禁止连续三个或更多相同字符。

两个入口现复用同一生成器：保留 18 字节加密随机源，以 Base64URL 缩为 28 位总长度；生成后执行完整本地密码规则校验，无效候选有界重选，随机源失败不回退固定密码。面板手动输入、服务端验证和 Python 购号前验证同步禁止连续三次相同字符；合法的两次重复保持可用。旧任务、账号凭据及既有激活账号不改写。

验证包括确定性无效随机候选后重新生成、随机源失败、候选重试上限、三类重复字符拒绝及合法双字符通过。Go 面板测试、182 项 Python 编排测试和隔离面板浏览器测试通过。原实网任务自行结束，最终记录为 `registration_captcha_unresolved`，尚未创建账号；本轮没有恢复或重开该任务。确认无活跃注册任务后，仅更新面板到 `dashboard-local-chrome-v3.exe`，三个既有 worker 的 PID、启动时间与路径保持一致。新密码策略仍需后续完整实网验收。
