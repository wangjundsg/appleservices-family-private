# 本机 Chrome 路径与验收边界

面板“新建 Apple ID”可选择本机 Chrome 或 Forge 指纹浏览器。选择在当前浏览器记忆，任务将 `browser_mode` 固定到私有清单；旧任务缺省仍为 Forge。两种方式共用现有 `pipeline.py → create-account.cjs → dashboard_handoff`，没有新增注册或激活 HTTP 接口。

本机 Chrome 直接启动本机安装的 Chrome，不调用 Forge，也不要求 Forge 凭据。使用浏览器原生环境，不加载创建器旧的指纹覆盖。图形校验保留人工答案文件；自动邮箱读取、短信等待、一次重发、同会话换号与新码交接仍沿用原实现。

本机网络可选择直连，或注册资源中的 `localBrowserProxy`。代理必须为带显式端口、无凭据的本机 HTTP、HTTPS 或 SOCKS5 地址；不自动寻找端口或切换出口。选定代理复制进该任务，修改资源设置不迁移旧任务。Forge 继续使用自己的代理与预检。

原激活启动器未加载注册配置和供应商环境，运行面板因此显示注册资源缺失。`tools/start-activation-dashboard.ps1` 增加可选 `-RegisterConfig`，复用 `provider-environment.ps1` 加载已有凭据；`-AllowPurchase` 必须同时指定注册配置。默认仍不购号、不恢复后台任务。私有配置和凭据不提交。

葡萄牙 Hero 的既有真实回执显示一小时有效期，旧代码只接受最多半小时。本轮先用脱敏回执复现错误，再将葡萄牙普通订单的有效期上限修为一小时；仍核验实际起止时间、金额、币种和后续接码能力，不延长供应商给定租期。

## 本轮验证

- 真实本机 Chrome 启动检查、本地表单的读回和短信菜单操作通过；未跳过 Chrome 测试。启动检查使用 `create-account.cjs --native-browser --browser-check`，不读取供应商或访问 Apple。
- Python 集成测试验证本机任务不调用 Forge、继续使用原创建器、换号后激活读取新订单、排除注册旧码，并沿用原面板交接直到在线回执。面板及供应商回执是测试替身，不代表实网验收。
- Go 测试覆盖方式与网络组合、代理校验、无 Forge 配置启动本机任务、私有清单固定配置、任务回读与旧任务兼容。
- 页面实际验证方式切换、刷新后记忆、网络选项及 390px 布局。

生产只读预检时没有正在执行的注册任务，但没有绑定邮箱订单，购号与供应商环境未启用。真实创建至激活的完整验收仍需可用的新订单及在场人工图形校验；本地测试不能替代这一结果。已有激活账号无需重登或重启。

## 单号实网发现与修复

新版面板已部署，三个既有 worker 的 PID、启动时间和映像路径未变。使用原 API 购买一个 Gmail 订单（700 VND），经现有面板绑定后启动本机 Chrome、葡萄牙、仅建号和激活的任务。原购号器取得一个葡萄牙号码（0.065 USD）。

首次执行在打开浏览器前返回 `usage / invalid activation expiry`，未向 Apple 提交注册。原因是共享 JS 生命周期仍只接受未来 30 分钟以内的到期时间。新增失败测试后，将上限与既有支持的一小时、一天租期对齐，仍使用订单实际到期时间。

另外，本地参数错误被旧编排误记为创建拒绝，并进入换号分支。现在退出码 2 单独记为 `registration_input_invalid`，保留号码，不结算或自动换号；只在已确认没有提交的情况下允许原任务恢复。换号分支同时保留供应商和租期策略，防止回退到默认供应商。

已核实原订单仍为 `PURCHASED / STATUS_WAIT_CODE`，只有一次号码购买。旧分支丢失的任务短信字段从同任务冻结清单、原创建输入和已购买回执恢复，原证据备份到私有目录。随后使用既有 `pipeline.py resume` 继续同一任务，无新购号、无更换邮箱、无直接调用 Apple 创建接口。实际浏览器已进入 `form_running`；完整实网结果待后续记录。
